# 繁体竖排资料数字化 Skill

> 一句话：**先判断源文件有没有真文本层，有就直接提取，没有就用 ViewImage 逐页视觉转录（右→左、上→下），最后用 organize 脚本统一清洗、做目录、按卷拆分、加锚点。**
>
> 本 Skill 由两件真实活件的经验归纳而来：韦千里《千里命稿》（Word97 `.doc`，有文本层）与《九灵铁经·气功针经合璧》《回到你的内在权威》（扫描 PDF / 内嵌图 docx，无文本层）。

---

## 〇、边界：做什么、不做什么

| 做 | 不做 |
|---|---|
| 繁体、竖排、右起的传统资料数字化 | 简体横排现代文档（直接复制即可，无需本流程） |
| 「有文本层 → 提取」或「纯图片 → 视觉转录」两条路径 | 用 paddle-ocr 跑竖排（实测失败，见 §三.3） |
| 清洗分页噪声、做目录、按卷拆分、加跳转锚点 | 校勘、标点、译文、重排版式（超出范围） |
| 保留原稿字误与异体字（数字化不等于润色） | 擅改原文 |

**核心判据**：打开源文件，看能否拿到「按阅读顺序排好的字符流」。
- 能 → 路径 A（提取），**不要 OCR**，OCR 反而丢字、错位。
- 不能（只有图）→ 路径 B（视觉转录）。

## 一、何时启用 / 不适用

| 启用 | 不适用 |
|---|---|
| 扫描版繁体竖排 PDF、内嵌图 docx | 本身就是可复制文本的 PDF/网页 |
| Word97–2003 `.doc`（OLE2 容器） | 需要 OCR 识别手写体、表格图 |
| 旧讲义、古籍、民国排印本数字化 | 需要版面还原（保留双栏/眉批位置） |

## 二、路径 A：源文件有文本层 → 直接提取（首选，零转录误差）

> 关键认知：**竖排只影响视觉排版，不影响底层字符的存储顺序**。Word/PDF 里的字符本就按「右列→左列、每列上→下」的阅读顺序存。所以提取出来的文本顺序天然正确，比任何 OCR 都准。

### A1. `.docx`（OOXML，把后缀改 .zip 能解）

1. 解包：`unzip -o book.docx -d book_unzip`
2. 文本在 `word/document.xml`，所有正文落在 `<w:t>...</w:t>` 之间。
3. 用正则把 `<w:t>` 内容按顺序拼接即可；段落以 `</w:p>` 为界换一行。
4. 竖排不改顺序，无需旋转或重排。

> 若 `document.xml` 里**完全没有 CJK 字符**（像《回到你的内在权威》那本：324 张内嵌 JPEG、document.xml 是空的），说明它是「图片型 docx」——**退回路径 B**。

### A2. `.doc`（Word97–2003，OLE2/CFB 复合文档）

文本不在明面，藏在 `WordDocument` 流里，需要按 **FIB + 片段表(CLX)** 还原。本工作区已验证的最小读取器：`tools/ole2_extract.js`（纯 Node，无依赖，能列流、导出任意流）。

**稳妥做法（推荐）**：优先用现成工具，它们已经把片段表和解压做对了、且保留阅读顺序：
- `libreoffice --headless --convert-to txt:Text book.doc` （最省心）
- 或 `antiword book.doc` / `catdoc book.doc`

**手动做法（无上述工具时，本工作区实际走的路）**：
1. 用 `tmp_ole.js` 导出 `WordDocument`、`0Table`/`1Table`（Table 流名看 FIB 的 `fWhichTblStm`）两个流。
2. 解析 FIB 头部关键偏移（Word97 稳定）：
   - `fcMin`（正文起始）@ `0x18`（4 字节 LE）
   - `ccpText`（正文字符数）@ `0x4C`（4 字节 LE）
   - `fcClx` @ `0x1A2`、`lcbClx` @ `0x1A6`（CLX 在 Table 流里的位置与长度）
3. CLX 结构：先可能有若干 `Prc`（跳过 `1 + n*8` 字节），接着 `0x02` 起头的 `Pcdt`：4 字节 `lcb` + PLC。
   - PLC = `(n+1)` 个 4 字节 CP 边界 + `n` 个 8 字节 `PCD`。`n = (lcb-4)/12`。
   - 每个 `PCD` 首 4 字节是 `FcCompressed`：**bit30 = fCompressed**；实际偏移 `fc = FcCompressed & 0x3FFFFFFF`。
   - **fCompressed=1 的片段是「1 字节压缩」**：每字节装 2 个码位（UTF-16 高字节丢失），该片段内字节偏移 = `fc/2 + (cp - cpStart)/2`。读出来后每字节展开成两个码位。
   - fCompressed=0 的片段是普通 UTF-16LE，偏移 = `fc`，按 `cp-cpStart` 取 `(cpEnd-cpStart)*2` 字节解码。
4. 把所有片段按 CP 顺序拼起来，`0x0D`→换行，`0x07` 等控制字符按需要清理。

> 这是《千里命稿》实际提取方式：导出流后按上面算法逐字还原，得到 107,783 字符 / 3,843 行，原稿字误（如「水火肾」）一律保留，未做任何润色。

## 三、路径 B：纯图片 → ViewImage 视觉转录

> 适用：扫描 PDF、内嵌图的 docx、任何没有可选文本层的源。**paddle-ocr-v4-mobile 在此机实测失败**（竖排被当成横排左→右读，置信度 0.18–0.32；且拒绝工作区外路径；本机也无 Python/PIL/ImageMagick 可旋转），所以走「人眼 + 视觉模型」逐页转录。

### B1. 把页面变成可喂给 ViewImage 的图

- PDF：用 `pdfjs-dist` + `@napi-rs/canvas` 逐页渲染（本仓库 `tools/render.js`），或任何能出 PNG/JPEG 的渲染器。
- docx：改后缀 .zip 解包，图片在 `word/media/`，**`imageN.jpeg` 的文件名顺序即真实页码顺序**（已验证，不要自己重排）。

### B2. 转录提示词（每页必含的三句话）

```
请逐字转录这张繁体竖排书页。
规则：按列从右往左读，每列从上往下读；
遇到横向排版的一行（如页眉、注释、横排引文）单独标 [横排]。
只输出原文，不要翻译、不要润色、保留异体字与明显字误。
```

- 竖排古籍常有几行**横排**小字（眉批、校记、考注），不标 `[横排]` 会被模型并进竖排列、顺序错乱。这是最容易翻车的地方，提示词必须强调。

### B3. 批处理与节流

- 一次喂 **5–6 页** 一批。实测大于 ~6 页的并行批次会偶发空输出（瞬时限流），小批量最稳。
- 每批落一个 `page_NN.txt`，文件名带页码，后面拼接脚本靠它排序。

### B4. 4 种页码标记样式（转录时各家用法不一，拼接脚本都要认）

| 样式 | 例 |
|---|---|
| 方头括号 | `【第12頁】` |
| 龟甲括号 | `〔12〕` |
| 等号分隔 | `======== 第 12 頁 ========` |
| 圆括号 | `（第12頁）` |

### B5. 拼接：assemble.js

`tools/assemble.js` 是已验证的拼接器：
- 按文件名页码或标记里的页码归并，去重、报缺失页（诊断 `missing 1-324`）。
- 统一重写成 `【第N頁】\n正文` 的规范格式，喂给下游 organize 脚本。
- 一份源可能混用多种标记样式，正则 `/(?:【第(\d+)頁】|〔(\d{1,3})〕|======== 第 (\d+) 頁 ========|（第(\d+)頁）)/g` 一次全认。

## 四、整理脚本：organize_template.py（清洗 + 目录 + 分卷 + 锚点）

路径 A 或 B 产出「带 `【第N頁】` 标记的裸文本」后，用本脚本统一整理。本工作区同款逻辑已在《九灵铁经合璧》上验证（7 卷 59 篇，重跑可自动增收补录的卷）。

**它做四件事**：
1. **提取目录**：从正文前的目次，按 `卷之X` / `篇第X`  Regex 抓「卷 → 篇（起页）」，用 `OrderedDict` 动态分组（**不硬编码卷数**）。
2. **清洗正文**：
   - 丢弃 `【第N頁】` 分页标记；
   - **按分页感知地接回段落**——上一页末句没断（不以 `。！？」）` 结尾）就与本页首行拼接，跨中间空行也接；
   - 舍去纯页脚行 `（頁腳）…`（`PAGE_FOOT_RE`）；
   - 保留篇题、考注、校记（这些行不参与接回）。
3. **输出整理版 + 独立目录 md**：目录按卷分组，含每篇起页；卷数/篇数全部动态推算。
4. **按卷拆分独立文件**：`分卷/<卷名>.md`，每卷头部带「本卷目录」小目录（可点击跳转），每个真实篇题前注入 `<a id="篇第X"></a>` 锚点；小目录项写成 `[篇名（起第N頁）](#篇第X)` 形式。

**可复用性**：脚本顶部把书相关的几处做成常量，换书只改常量：
- `BODY_MARKERS`：正文起始行（如 `("九靈鐵經正文", "九灵铁经正文")`），脚本只在此行之后做「卷→篇」抓取与拆分；繁简混用就给元组。
- `BOOK_PREFIXES`：卷首行必须以书名开头（如 `("鐵經", "鍼經")`），否则「（卷之六）」「參本書卷之五」之类注脚会被误抓成卷。
- `HEAD_MARKERS`：识别标题行的关键词集合（卷之/篇第/考注/凡例/书目/目次…）；
- `juan_re` / `pian_re`：卷、篇的匹配正则（繁体数字 `一二三四五六七八九十`）；
- 分页标记格式、`PAGE_FOOT_RE`。

**两个易错点（已在原稿踩过）**：
- 考注里若**提及他篇**（如「参见《示色脈診治篇第四十三》」），会被朴素「篇第」正则误抓成篇。原脚本用 `pian in tocs_pian and st.startswith(pian)` 双重过滤：只给「既是目录真篇、又整行以该篇名开头」的行打锚点， citation 行自动排除。
- 卷首行正则别画蛇添足要求结尾有 `/`——原稿目次有的写「卷之八／」有的写「卷之八」，写成 `^(鐵經|鍼經).+?卷之[一二三四五六七八九十]+` 即可，否则一页都匹配不上、卷数归零。

## 五、硬规则（违反即视为不合格数字化）

1. **先判文本层，再决定路径**：有文本层的书去跑 OCR 是倒退，正文顺序与字准度都会掉。
2. **竖排只影响视觉，不影响提取顺序**：docx/doc 提取出的文本顺序天然正确，不要旋转、不要重排。
3. **图片型 docx 会伪装成「有文本」**：`document.xml` 为空就退回路径 B，别被 `.docx` 后缀骗了。
4. **横排小字必须标 `[横排]`**：这是视觉转录唯一高频翻车点。
5. **保留原稿字误与异体字**：数字化是搬运，不是校勘；润色留给下游。
6. **批大小 5–6 页**：更大批次会偶发空输出。
7. **分页感知接回段落**：直接按空行断句会把跨页的一句话劈成两半；必须看上一页句尾是否断句。
8. **卷/篇数动态推算**：别把卷数、篇数写死，补录新卷后重跑脚本应能自动增收（这是整理版可长期维护的前提）。

## 六、验收

| 检查项 | 通过标准 |
|---|---|
| 文本层路径 | 提取文本字符数合理、无乱码、阅读顺序与原文一致 |
| 图片路径 | 拼接后 `missing` 列表为空或仅缺明确未转录页；无整页空输出 |
| 清洗 | 整理版中 `【第N頁】` 计数为 0；`（頁腳）` 计数为 0；跨页句已接回（抽样读 3–5 处换页处） |
| 目录 | 卷数/篇数与原稿目次一致；起页号正确 |
| 分卷 | 每卷文件存在；小目录链接可跳；锚点 `<a id="篇第X">` 恰在真实篇题前（考注提及他篇处无锚点） |
| 可维护性 | 往源稿补录一卷并重跑，目录与分卷自动增收，无需改代码 |
